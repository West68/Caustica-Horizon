# DH 原始面片紧凑光追表示

用户截图中的树林色块由 Caustica 的 DhLodProxy 二次高度场简化产生。DH 自己的 Section/Quad 已含更精细的轮廓。直接提高旧三角形展开预算会按每 Quad 200 字节几何加两个三角形 AS 消耗显存，继续高度场则丢失树木和垂直层，均不合适。

改为每 Quad 一个 32 字节记录：前 24 字节为 VkAabbPositionsKHR，后 8 字节保存原始颜色、面向、纹理和水/玻璃标志。硬件 BVH 筛选候选，intersection shader 精确求原来的轴对齐矩形平面，并非求交实心包围盒。沿法线略微扩大 bbox 只为避免退化；实际平面、水顶 8/9 高度、纹理及原有材质计算保持一致。沿用同一积分器、光线数和现有构建/同步提交。

停止调用 DhLodProxy 和 DhLodBudgetPlan；使用驱动查询的 AS/scratch 实际大小准入，累计上限 768 MiB，包含延迟释放的旧资源。原子父子接替和维度命名空间机制保留。每帧至多四个 Section，65,536 Quad 的软工作阈值（单个大 Section 必须能完成）。预算不足时暂留完整旧父，不重造有损高度场；此极端状态必须在报告中明确，不能承诺无限细节。

验证：全部面向与水边缘对照旧三角形，6,000 条射线对照独立 Moller-Trumbore；SPIR-V 验证；完整隔离实例固定观察点、维度往返、GPU 回读、帧时间及显存观测。早期实验漏设 query geometryCount 导致过小 AS 分配，已修正为显式 1；失败记录保留，不能当通过。正式候选以最后实际运行的 JAR 哈希为准。

CPU 捕获进一步使用不可变 3×long 数组保存每个源 Quad（24 字节，所有源字段逐位保留），GPU 上传直接解包，不生成逐 Quad 临时 record。4096 个随机 Quad 验证 List 接口与 GPU 字节输出一致；烘焙光照变化不会改动光追几何版本。最终完整回归的近景实例恢复至1332，413个LOD实例保留约694万原始面片。完整数据及未通过验证项见 reports/dh-exact-rectangles12.json。
